# 数据源参数、Task 同步参数与多标签工作台设计

## 背景与目标

当前系统设置把数据源、历史深度、重叠天数、超时、重试等混在一起，但这些参数实际服务于日线同步 Task。用户希望按职责重新拆分：系统只管理数据源连接，具体同步行为由每次 Task 启动参数决定；同时把左侧路由导航改成可保留页面状态的多标签工作台。

## 已确认的用户决策

1. A／港／美／加密的 `provider` 和 `request_timeout_seconds` 仍由系统“数据源配置”页面展示并支持修改。
2. 最大重试改为 0，并从代码中移除自动重试逻辑，而不是仅隐藏配置。
3. `history_years`、`overlap_days`、`concurrency`、`adjustment` 全部移到各日线同步 Task 的启动参数并支持修改。
4. 系统设置下新增“数据源配置”子菜单，页面只展示数据源相关配置。
5. 页面切换改成多标签：重复打开已有标签只激活，已打开页面保持挂载；标签可关闭；关闭最后一个标签后显示空白工作台。

## 范围外

- 不新增行情源，不修改指标公式、图表类型或已入库 K 线格式。
- 不重写证券列表同步、指标计算 API 或前端指标选择器。
- 不把时区、指标数量上限移入“数据源配置”页面；它们继续由后端现有全局配置管理。
- 不用浏览器 localStorage 持久化标签；标签只在当前 AppShell 生命周期内有效，刷新页面按默认首页重新开始。
- 不自动 commit 或 push。

## 后端配置与兼容

### 市场级配置

`MarketSettings` 精简为：

- `provider`
- `symbols`（仍仅用于加密货币交易对目录）
- `request_timeout_seconds`

移除 `history_years`、`overlap_days`、`concurrency`、`max_retries` 及其前端类型、decoder、表单和测试。`ConfigService._read_settings` 在 Pydantic 校验前执行一次性兼容迁移：如果旧市场存在这些字段，而对应日线 Task 尚未显式设置同名参数，就把旧值复制到该 Task 的 params；Task 已有值始终优先。随后过滤市场级废弃字段，保留 `schema_version=1` 和现有 revision，不要求用户手工改文件，也不因启动迁移而额外增加 revision；下一次正常保存时自然写成精简结构。这样旧市场里的非默认历史深度和重叠窗口不会在升级后被静默重置。`max_retries` 按新需求直接废弃，不迁入 Task。

`provider` 仍决定 A／港／美股票的实际适配器。加密货币继续由每个交易对的 `exchange` 决定实际交易所；市场级 `provider` 不覆盖交易对。

### 日线 Task 参数

四个日线 Task 共用参数模型，保留 `universe_codes`、`symbols`、`full_refresh`，新增：

| 参数 | 默认与允许值 | 用途 |
|---|---|---|
| `history_years` | 股票默认 10 年，加密默认全部可用历史；正整数或 null | 全量下载的起始时间 |
| `overlap_days` | 默认 45，1–366 | 增量下载的重叠窗口 |
| `concurrency` | 默认 1，1–8 | 单个 Task 内同时下载的证券数 |
| `adjustment` | 默认 `auto`；可选 `qfq`、`none` | 价格复权方式及元数据校验 |

`auto` 保持现有行为：普通股票 `qfq`，指数与加密现货 `none`。空参数使用上述默认值，因此现有 Task 配置无需手工补字段。Task 参数继续经过 Pydantic 校验、配置快照和运行历史记录，RJSF 表单直接复用生成的 schema，不为四个市场复制页面。

### 无重试语义

`BarSyncService` 和 provider 调用链只发起一次请求，不再进行指数退避、Retry-After 等待或自动重试。限流和不可用仍作为真实错误记录，不伪装成功。删除 `max_retries` 配置及只为重试服务的参数、常量和辅助函数；保留必要的错误类型与诊断信息。

### 历史与复权

用不可变的同步选项对象把 Task 参数传给 `BarSyncService`，不把这些字段重新塞回 `MarketSettings`。全量下载使用 `history_years`；增量下载使用 `overlap_days`。价格来源或复权方式变化仍触发全量替换，空增量仍保留已有数据。

### 并发

单个日线 Task 使用 `asyncio.Semaphore` 限制同时执行的证券数，默认 1 时保持现有顺序和结果语义。每个证券继续独立下载、独立事务、独立成功／失败记录；限流或单票失败不影响其他证券。进度与日志按完成顺序输出，最终统计按原证券顺序聚合，避免共享可变计数器。仓储与指标缓存只在事件循环内进行原子状态更新，不引入跨线程共享连接。

## 前端数据源配置

`MarketSettingsForm` 精简为：

- 各市场数据源选择。
- 各市场超时秒数，保留 0–300 秒范围内的正数校验。
- 加密货币交易对编辑。

删除历史深度、最大重试、重叠天数、并发和复权展示。前端类型与运行时 decoder 同步收紧，保存时不再发送已删除字段。后端全局时区和指标上限不作为本页内容。

左侧“系统设置”变为可展开菜单，新增 `/settings/data-sources` 子菜单“数据源配置”。`/settings` 重定向到该路由，旧的直接链接仍可打开。

## 多标签工作台

### 标签模型

AppShell 持有不可变标签数组：默认打开“图表分析”。每个标签记录稳定路由 key、标题和首次创建的 React outlet 内容。稳定 key 只取 `location.pathname`，忽略 query/hash；当前仅有 `/analysis`、`/tasks`、`/settings/data-sources` 三种页面，没有按证券或 Task 详情划分的动态路由，因此同一路径始终复用同一个标签和页面实例。若未来增加动态业务路由，必须另行设计其 key，不在本次范围内。

- 点击菜单或标签时导航到对应路由；若 key 不存在则追加，已存在则只激活，不重建页面。
- 标签区域置于 body 顶部，支持激活和关闭，样式沿用现有深色主题。
- 所有打开页面保持 React 挂载，非活动页面仅隐藏。这样表单、指标实例、Task 抽屉、设置编辑和图表状态不会因切换丢失。
- URL 继续与实际路由同步，浏览器前进／后退和直接链接仍可工作。
- 关闭活动标签时激活相邻标签；关闭最后一个标签后导航到专用 `/blank` 路由并显示空白工作台，不自动重新打开首页。`/blank` 不属于任何菜单标签，避免关闭动作被路由监听再次打开。
- 关闭标签会卸载对应页面。若关闭最后一个图表分析标签，分析会话 Provider 也重置，避免重开时意外恢复已关闭页面的状态。

### 隐藏页面副作用

- Lightweight Charts 的 ResizeObserver 在重新显示时重新测量并应用精确 pane 高度，忽略隐藏时的 0 尺寸。
- Task 运行中的轮询可在后台标签继续，符合页面保持打开和任务后台运行的预期；关闭标签会按现有清理逻辑停止轮询。
- 不为 Ant Tabs 使用默认的卸载式内容区域；标签按钮只负责导航，页面内容由 Workspace 自行缓存和隐藏。

## 测试与验收

采用 TDD，先后端契约再前端行为：

1. 配置模型与旧文件迁移：旧字段被兼容读取并迁入对应 Task，Task 已有参数优先，新文件不再包含废弃字段；超时仍可热更新。
2. 无重试：限流、不可用及 Retry-After 场景均只调用一次 provider。
3. Task 参数：默认值、边界、快照和各市场 adjustment 行为；空参数保持现有结果。
4. 并发：1 时顺序语义不变，>1 时有界并行、单票失败隔离、进度和统计正确。
5. 前端设置：精简字段、运行时 decoder、保存和子菜单路由。
6. 多标签：首次打开、重复激活、状态保留、关闭活动／非活动标签、关闭最后一个、URL 前进后退、Task 轮询清理和图表恢复。
7. 全量后端 pytest、前端 Vitest／覆盖率、TypeScript/Vite build、Playwright 与真实本地页面验收。

## 实施约束

- 保持不可变配置快照和 React 状态更新。
- 优先复用现有 RJSF、ProviderRegistry、Task 参数验证、Workspace/Session 和图表 ResizeObserver，不引入新的状态管理库。
- 兼容现有配置文件和直接 URL，不要求用户手工迁移。
- 工作目录继续使用当前 `main` 工作区，不自动提交。
